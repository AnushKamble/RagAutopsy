# RAG-Autopsy: Trace Schema & Observability Boundary Specification

This document specifies the exact data contracts, observability boundaries, serialization formats, and leakage-prevention guarantees separating runtime diagnostic traces from privileged evaluation ground truth in RAG-Autopsy.

---

## 1. Architectural Separation Principle

A central scientific contribution of RAG-Autopsy is enforcing that **diagnostic routines operate strictly on unprivileged runtime observability signals** that any standard production RAG system could realistically capture, without ever accessing ground-truth labels, injected fault IDs, or evaluator keys.

```text
+-----------------------------------------------------------------------------------+
|                              RAG Pipeline Runtime                                 |
|  Question + Corpus ---> Retriever ---> Context Assembler ---> Generator           |
|                              |                  |                 |               |
|                              +------------------+-----------------+               |
|                                                 |                                 |
|                                       [DiagnosticTrace]                           |
|                         (Pydantic model, extra="forbid", validated)               |
+-------------------------------------------------|---------------------------------+
                                                  |
                                                  v
                               +-------------------------------------+
                               |          Diagnostic API             |
                               |    BaseDiagnostic.diagnose(trace)   |
                               |  (D1: Retrieval, D2: Lexical, etc.) |
                               +------------------|------------------+
                                                  |
                                                  v
                                             [Diagnosis]
                                                  |
    +--------------------------------------+      |
    |          EvaluatorStore              |      |
    |   [EvaluatorRecord keyed by UUID]    |      |
    | (injected_fault, gold_answers, etc.) |      |
    +-------------------|------------------+      |
                        |                         |
                        +------------+------------+
                                     |
                                     v
                 [explicit_evaluation_join on trial_id]
                                     |
                                     v
                       [Attribution Evaluation Benchmarks]
```

## 2. Schema Specification

### 2.1 `DiagnosticTrace` (Diagnostic-Visible Only)

- **Class:** [`DiagnosticTrace`](../src/rag_autopsy/core/schemas.py)
- **Constraint:** `model_config = ConfigDict(extra="forbid")`
- **Visibility:** Unprivileged runtime diagnosers, attribution policies, and logging handlers.

| Field Name | Type | Description | Operational Justification |
|---|---|---|---|
| `schema_version` | `str` | Schema version (e.g., `"1.0.0"`). | Contract compatibility across releases. |
| `trial_id` | `str` | Opaque 16-hex hash prefixed by `"trial_"`. | Stable identifier for post-hoc join. Must NOT encode fault tokens. |
| `question_id` | `str` | Stable dataset question identifier. | Query identification and question-grouped bootstrap clustering. |
| `question` | `str` | Natural language user query text. | Realistic observable input to retrieval and generation. |
| `retrieved_top_k` | `List[RetrievedPassage]` | Top-$k$ retrieved passages with ranks, BM25 scores, and text. | Standard retriever output passed into context assembly. |
| `candidate_pool_scores` | `Optional[List[float]]` | Sorted float scores for top-$K$ candidates (e.g. $K=20$). | Score distribution to detect score cliffs (Regime A) without leaking text. |
| `source_passage_ids` | `List[str]` | IDs of retrieved candidate passages. | Audit trail of retriever candidates. |
| `pre_assembly_passage_ids`| `List[str]` | Passage IDs prior to prompt context assembly. | Allows structural diff against post-assembly passages. |
| `post_assembly_passage_ids`| `List[str]` | Passage IDs retained in prompt context. | Allows detection of transit context drops (F3) without semantic models. |
| `generator_context` | `str` | Complete assembled prompt text sent to generator. | Generator input string for grounding / NLI checks. |
| `answer` | `str` | Final text generated by LLM / extractor. | Generated answer string for support evaluation. |
| `latency_ms` | `float` | Pipeline execution latency in milliseconds. | System performance monitoring (not used as diagnostic feature). |
| `generator_model` | `Optional[str]` | Generator model/adapter identifier string. | Provenance and auditing metadata. |
| `generator_config` | `Dict[str, Any]` | Non-sensitive generation parameters (e.g. temperature). | Cache invalidation key. |
| `metadata` | `Dict[str, Any]` | Unprivileged execution parameters (top_k, max_chars). | Strict validator rejects any forbidden keys, values, or objects. |

### 2.2 `RetrievedPassage` (Passage Item Schema)

- **Class:** [`RetrievedPassage`](../src/rag_autopsy/core/schemas.py)
- **Constraint:** `model_config = ConfigDict(extra="forbid")`

| Field Name | Type | Description |
|---|---|---|
| `passage_id` | `str` | Corpus-wide passage identifier. |
| `rank` | `int` | 1-indexed retrieval rank ($1 \le \text{rank} \le k$). |
| `score` | `float` | Retrieval relevance score (BM25 or cosine similarity). |
| `text` | `str` | Raw text of retrieved passage chunk. |
| `title` | `Optional[str]` | Source article or document title. |

### 2.3 `EvaluatorRecord` (Privileged Ground Truth)

- **Class:** [`EvaluatorRecord`](../src/rag_autopsy/core/schemas.py)
- **Constraint:** `model_config = ConfigDict(extra="forbid")`
- **Visibility:** Evaluator only. Never passed to `BaseDiagnostic.diagnose()`.

| Field Name | Type | Description |
|---|---|---|
| `trial_id` | `str` | Opaque trial ID matching the corresponding `DiagnosticTrace`. |
| `question_id` | `str` | Question identifier matching the corresponding `DiagnosticTrace`. |
| `split` | `str` | Partition split: `"dev"`, `"calibration"`, or `"test"`. |
| `injected_fault` | `str` | Ground-truth fault intervention: `"F0"`, `"F1"`, `"F2"`, `"F3"`, `"F4"`, or `"F5"`. |
| `fault_parameters` | `Dict[str, Any]` | Exact parameters used during intervention injection. |
| `gold_answers` | `List[str]` | Reference answer strings from gold dataset. |
| `gold_evidence_ids` | `List[str]` | Passage IDs marked as supporting facts in dataset annotations. |
| `injection_applied` | `bool` | Whether the injector successfully executed its mutation. |
| `trace_condition_achieved` | `bool` | Whether the post-intervention state matched the target condition. |
| `trial_valid` | `bool` | Adjudicated validity for inclusion in attribution evaluation. |
| `invalid_reason` | `Optional[str]` | Detailed reason if injection was discarded as invalid. |
| `answer_exact_match` | `Optional[bool]` | Post-hoc Exact Match evaluation score. |
| `answer_token_f1` | `Optional[float]` | Post-hoc Token F1 evaluation score. |
| `answer_supported_by_context` | `Optional[bool]` | Post-hoc reference support heuristic. |

## 4. Leakage Pathway Audit & Verification

RAG-Autopsy validates that privileged information cannot reach diagnostics across nine explicit vectors:

| Leakage Pathway | Threat Vector | Mitigation & Technical Enforcement | Automated Test Proof |
|---|---|---|---|
| **Direct Field Access** | Diagnoser accesses `trace.injected_fault` or `trace.gold_answers`. | `DiagnosticTrace` schema does not define any evaluator fields. `extra="forbid"` rejects initialization. | `test_diagnostic_trace_has_no_evaluator_fields`, `test_extra_fields_forbidden_in_diagnostic_trace` |
| **Passage-Level Smuggling** | Retriever attaches `is_gold_evidence` onto `RetrievedPassage`. | `RetrievedPassage` sets `model_config = ConfigDict(extra="forbid")`. | `test_extra_fields_forbidden_in_retrieved_passage` |
| **Metadata Smuggling** | Evaluator smuggles `{"injected_fault": "F1"}` or `EvaluatorRecord` in `trace.metadata`. | `verify_no_leakage` checks keys, string tokens, and rejects any object with evaluator attributes. | `test_leakage_rejection_in_metadata_key`, `test_metadata_evaluator_object_smuggling_rejected` |
| **Label-Encoding IDs** | Diagnoser parses fault name from `trial_id` (e.g. `trial_f1_01`). | `generate_stable_trial_id()` generates SHA-256 hashes (`trial_8f4a...`). Validator enforces regex `FAULT_TOKEN_PATTERN`. | `test_leakage_rejection_in_trial_id`, `test_stable_non_label_encoding_ids` |
| **Sort Order / Modulo Bias** | Trials ordered sequentially `[F0, F1, F2...]` allowing index modulo guessing. | `run_experiment_harness` shuffles trial presentation order with seeded PRNG (`random.Random(seed).shuffle()`). | `test_sort_order_decoupling_prevents_modulo_attack` |
| **Generator Cache Keys** | Caching generator stores or hashes ground-truth evaluator metadata. | `CachedGenerator.compute_cache_key()` hashes only model name, config, question, and context. | `test_cached_generator_keys_contain_no_evaluator_data` |
| **NLI Diagnostic Cache** | NLI cache contains gold answers or labels. | `D3NLISupportDiagnostic._compute_cache_key()` hashes strictly premise and hypothesis strings. | `test_d3_nli_cache_keys_contain_no_evaluator_data` |
| **File Boundary Mixing** | Traces and evaluation records stored in the same JSON/CSV stream. | Stored in physically separate files (`diagnostic_traces.jsonl` vs `evaluator_records.jsonl`). Deserialization cross-loading raises `ValidationError`. | `test_file_boundary_separate_jsonl_serialization` |
| **Convenience Wrapper Backdoors** | Passing a compound `TrialRecord(trace, evaluator_record)` to diagnostic. | `BaseDiagnostic.diagnose()` enforces `type(trace) is DiagnosticTrace` and validates `hasattr(trace, forbidden)`. | `test_diagnostic_api_strictly_rejects_non_trace_types`, `test_diagnostic_api_rejects_tampered_trace` |

## 5. Indirect Leakage Pathways & Monitoring

Beyond direct field access, indirect statistical shortcuts can theoretically arise through subtle correlations. We continuously monitor and mitigate these:

1. **Context Length Correlates (F3 / F4):**
   - *Risk:* F3 (assembly loss) shortens context; F4 (contradiction injection) lengthens context by adding a conflicting sentence.
   - *Mitigation & Check:* In D4, context length is only one of 8 features. When evaluating on natural clean controls (F0), baseline length variation spans the range of injected modifications ($400 - 2,500$ characters).
2. **Lexical Perplexity / Formatting Artifacts:**
   - *Risk:* Synthetic contradictions or entity substitutions could introduce unnatural grammar or phrasing.
   - *Mitigation & Check:* Contradiction injector uses entity-preserving assertion reversals (e.g. negating numbers or dates), and F5 substitutes named entities with valid alternatives from the same corpus entity type.
3. **Latency Signatures:**
   - *Risk:* Retrieval on smaller corpus or generation on shorter context takes fewer milliseconds.
   - *Mitigation & Check:* Diagnosers are strictly prohibited from using `latency_ms` as a classification feature. `D4LearnedClassifierPolicy` does not include `latency_ms` in `FEATURE_NAMES`.
